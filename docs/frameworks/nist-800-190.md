# F4 — NIST SP 800-190 (Application Container Security Guide)

The definitive **container** control framework. It is outcome-oriented — it names *risks* and *countermeasures*
by lifecycle area, not exact settings. Below: each 800-190 risk area → the practical technical countermeasure →
the module that delivers it. This is the backbone the governance frameworks (F9–F14) crosswalk onto.

**Modules:** essentially all of them — 800-190 spans the whole lifecycle.

## The five major areas + countermeasures

### 4.1 Image risks
| Risk | Countermeasure | Module |
|---|---|---|
| Image vulnerabilities | scan every image; block on policy; continuous re-scan | `vuln` |
| Image config defects | non-root, no setuid, HEALTHCHECK, CIS-DI | `imageaudit`, `dockerfile` |
| Embedded secrets | detect in all layers; use build secrets | `secrets`, `dockerfile` |
| Untrusted images | sign + verify; trusted-registry allowlist | `verify` |
| Unknown contents | SBOM every image | `sbom` |

### 4.2 Registry risks
| Risk | Countermeasure | Module |
|---|---|---|
| Insecure connections | TLS + mutual auth to registry | `registry`, `dockerbench` |
| Stale images | retention/GC; re-scan stored images | `vuln`, `registry` |
| Insufficient authZ | per-repo RBAC, scoped robot tokens | `rbac`, `registry` |

### 4.3 Orchestrator risks
| Risk | Countermeasure | Module |
|---|---|---|
| Unbounded admin access | least-privilege RBAC; no wildcard | `rbac` |
| Poor inter-node trust | mTLS, node identity | (K8s — see [kubernetes.md](kubernetes.md)) |
| Mixed sensitivity workloads | segmentation, RuntimeClass, namespaces | `harden`, `netmon` (planned) |

### 4.4 Container (runtime) risks
| Risk | Countermeasure | Module |
|---|---|---|
| Vulnerable runtime software | patch runtime/daemon; scan node | `vuln`, `dockerbench` |
| Unbounded network access | default-deny egress; segmentation | `netmon` (planned) |
| Insecure runtime config | cap-drop, seccomp, no-new-privs, read-only, no privileged | `dockerbench`, `harden` (planned) |
| App vulnerabilities at runtime | behavioral detection, drift, escape | `runtime` (planned) |
| Rogue containers | admission policy; image provenance | `admission`/`policy` (in progress), `verify` |

### 4.5 Host OS risks
| Risk | Countermeasure | Module |
|---|---|---|
| Large attack surface | minimal, container-specific host OS | `dockerbench` host |
| Shared kernel | user namespaces, seccomp/MAC, sandbox (gVisor/Kata) | `harden` (planned) |
| Improper user access | audit host access to daemon/socket | `rbac`, `dockerbench` |
| Host FS tampering | monitor sensitive mounts; FIM | `runtime` (planned) |

## How we deliver it
800-190 is authored as a **control pack** whose entries mostly `maps_to` other frameworks and point at the
concrete technical checks above. Because 800-190 is the *container* control language, it is the **hub** of the
crosswalk: satisfy the technical checks once, and 800-190 coverage plus its downstream mappings (800-53, PCI,
ISO) light up together. Federal use is mandatory; everyone else gets a clean risk-based backbone.
